# 🎯 亚马逊SP API配置管理系统 - 项目说明

## 📌 项目概述

本项目实现了一个**完全可视化的亚马逊卖家API配置管理系统**，让用户无需手动编辑配置文件，通过现代化的Web界面即可轻松管理多个店铺的API配置。

**位置**: `amazon_sp_analytics/app/api/routes.py`

**已实现的端点**：

#### 配置管理API
```
GET    /api/config/stores           # 获取所有店铺配置
GET    /api/config/stores/{id}      # 获取指定店铺配置
POST   /api/config/stores           # 创建店铺配置
PUT    /api/config/stores/{id}      # 更新店铺配置
DELETE /api/config/stores/{id}      # 删除店铺配置
POST   /api/config/test             # 测试API配置
```

#### 其他端点

## 🎯 核心功能流程

### 添加店铺配置流程

```
1. 用户访问 http://localhost:8000
2. 点击"➕ 添加店铺"标签页
3. 填写店铺信息（ID、名称、API凭证等）
4. 点击"✅ 保存配置"
5. 前端发送POST请求到 /api/config/stores
6. 后端验证数据并创建StoreCredentials对象
7. 配置管理器将配置保存到stores_config.yaml
8. 返回成功响应
9. 前端显示成功提示并刷新列表
```

### 配置测试流程

```
1. 用户在"🔍 测试配置"页面输入API凭证
2. 点击"测试配置"按钮
3. 前端发送POST请求到 /api/config/test
4. 后端创建临时StoreCredentials对象
5. 尝试创建SPAPIClient并验证凭证
6. 返回测试结果（成功/失败）
7. 前端显示测试结果
```

### 编辑店铺流程

```
1. 用户在店铺列表点击"✏️ 编辑"
2. 前端发送GET请求获取店铺详情
3. 在模态框中显示当前配置
4. 用户修改配置后点击"保存"
5. 前端发送PUT请求到 /api/config/stores/{id}
6. 后端更新配置并保存到文件
7. 返回更新后的配置
8. 前端刷新店铺列表
```

## 🔧 技术实现细节

### 1. 前后端交互

**前端**：
- 纯HTML + CSS + JavaScript
- 使用Fetch API进行HTTP请求
- 实时DOM操作更新界面

**后端**：
- FastAPI框架
- RESTful API设计
- Pydantic数据验证

### 2. 配置持久化

**存储方式**：
- 使用YAML格式存储配置
- 文件路径：`stores_config.yaml`
- 支持手动编辑（向后兼容）

**配置结构**：
```yaml
global:
  # 全局配置
stores:
  # 店铺列表
  - store_id: xxx
    store_name: xxx
    ...
```

### 3. 数据验证

**使用Pydantic进行**：
- 输入数据验证
- 类型检查
- 自动生成API文档

**验证规则**：
- 必填字段检查
- 区域枚举验证
- Marketplace ID格式验证

### 4. 错误处理

**API层**：
- HTTPException for API errors
- 详细的错误消息
- 适当的HTTP状态码

**前端**：
- Try-catch捕获异常
- 用户友好的错误提示
- 操作失败反馈

### 5. 安全性考虑

**实现的安全措施**：
- ✅ Client Secret在列表中脱敏显示
- ✅ 编辑时密码字段可选更新
- ✅ 删除操作需要确认
- ✅ API错误不暴露敏感信息

**建议增强**（生产环境）：
- ⚠️ 添加用户认证
- ⚠️ 使用HTTPS
- ⚠️ IP白名单
- ⚠️ 配置文件加密
