# 🛒 亚马逊SP API数据分析系统 - 完整指南

## 📌 系统概述

这是一个**功能完整**的亚马逊卖家数据分析系统，具有以下核心特性：

✅ **可视化配置管理** - 无需手动编辑配置文件  
✅ **MySQL数据库存储** - 高性能数据存储和查询  
✅ **Reports API集成** - 批量获取销售和库存数据  
✅ **自动化调度** - 定时自动更新数据  
✅ **多店铺支持** - 同时管理多个亚马逊店铺

## 🎯 核心功能

### 1. 可视化配置管理界面

**无需手动编辑配置文件！**

- 📋 查看所有店铺配置
- ➕ 添加新店铺（填表单即可）
- ✏️ 编辑现有店铺
- 🗑️ 删除店铺
- 🔍 测试API凭证有效性

**启动方式**:
```bash
cd amazon_sp_analytics
./start.sh  # Linux/Mac
# 或
start.bat   # Windows

# 访问: http://localhost:8000
```

### 2. MySQL数据库集成

**为什么选择MySQL?**
- ⚡ 高性能查询
- 💾 大数据量存储
- 🔗 易于集成BI工具
- 📊 支持复杂分析

**数据表结构**:
- `stores` - 店铺信息
- `sales_reports` - 销售数据(按日期)
- `sales_reports_by_asin` - 销售数据(按商品)
- `inventory_reports` - 库存数据(汇总)
- `inventory_reports_by_asin` - 库存数据(按商品)
- `report_requests` - 报告请求记录

### 3. Reports API批量数据获取

**为什么使用Reports API而不是单独调用?**

| 对比项 | 单独API调用 | Reports API |
|--------|------------|------------|
| 效率 | ❌ 低 | ✅ 高 |
| API限流 | ❌ 容易触发 | ✅ 友好 |
| 数据完整性 | ❌ 可能遗漏 | ✅ 完整 |
| 官方推荐 | ❌ 不推荐 | ✅ 推荐 |

**支持的报告类型**:
- ✅ 销售和流量报告 (GET_SALES_AND_TRAFFIC_REPORT)
- ✅ 库存报告 (GET_VENDOR_INVENTORY_REPORT)
- ✅ 订单报告 (GET_FLAT_FILE_ALL_ORDERS_DATA)
- ✅ 财务报告 (GET_V2_SETTLEMENT_REPORT_DATA)

### 4. 自动化定时调度

**一次配置，自动运行**

设置定时任务后，系统会自动：
1. 每天指定时间请求报告
2. 等待报告生成完成
3. 下载并解析报告
4. 存入MySQL数据库

**无需人工干预！**

## 💡 使用场景

### 场景1：每日自动更新数据

```python
from app.config.sp_api_config import MultiStoreConfig
from app.models.mysql_manager import create_mysql_manager_from_config
from app.services.report_scheduler import ReportScheduler

# MySQL配置
mysql_config = {
    'host': 'localhost',
    'user': 'amazon_user',
    'password': '你的密码',
    'database': 'amazon_sp'
}

# 初始化
config_manager = MultiStoreConfig()
db_manager = create_mysql_manager_from_config(mysql_config)
scheduler = ReportScheduler(config_manager, db_manager)

# 设置定时任务
scheduler.schedule_sales_reports(time_str="02:00", days_ago=1)
scheduler.schedule_inventory_reports(time_str="03:00", days_ago=1)

# 启动
scheduler.start()
```

### 场景2：手动获取历史数据

```python
from app.services.report_service import ReportProcessingService

service = ReportProcessingService(db_manager)
stores = config_manager.get_all_stores()

# 获取最近30天的数据
results = service.process_all_stores_sales(stores, days_ago=30)
```

### 场景3：数据分析查询

```sql
-- 查询最近7天销售趋势
SELECT 
    report_date as 日期,
    SUM(units_ordered) as 订单数,
    SUM(ordered_product_sales) as 销售额,
    AVG(buy_box_percentage) as Buy_Box率
FROM sales_reports
WHERE report_date >= DATE_SUB(CURDATE(), INTERVAL 7 DAY)
GROUP BY report_date
ORDER BY report_date;

-- 查询Top 10商品
SELECT 
    parent_asin as ASIN,
    sku as SKU,
    SUM(units_ordered) as 销量,
    SUM(ordered_product_sales) as 销售额
FROM sales_reports_by_asin
WHERE report_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)
GROUP BY parent_asin, sku
ORDER BY 销量 DESC
LIMIT 10;
```

## ⚠️ 注意事项

### 1. API限流

Reports API限制：
- 创建报告: **0.0167 请求/秒** (约1次/分钟)
- 查询报告: **0.5 请求/秒**

**建议**：
- ✅ 使用定时任务，每天1-2次
- ✅ 避免频繁请求
- ✅ 实现重试机制

### 2. 数据延迟

- 销售数据: **24-48小时延迟**
- 库存数据: 相对实时

### 3. 报告类型选择

根据账号类型选择：
- **卖家 (Seller)**: `GET_SALES_AND_TRAFFIC_REPORT`
- **供应商 (Vendor)**: `GET_VENDOR_INVENTORY_REPORT`

### 4. 数据库维护

```sql
-- 定期清理旧数据
DELETE FROM sales_reports 
WHERE report_date < DATE_SUB(CURDATE(), INTERVAL 6 MONTH);

-- 优化表
OPTIMIZE TABLE sales_reports;
OPTIMIZE TABLE sales_reports_by_asin;
```

## 📞 常见问题

**Q: 可以获取实时数据吗？**  
A: 不可以。Reports API获取的是历史数据，有24-48小时延迟。

**Q: 报告生成需要多长时间？**  
A: 通常5-15分钟，系统会自动等待完成。

**Q: 支持多个Marketplace吗？**  
A: 支持。在配置中可以指定多个Marketplace ID。

**Q: 数据库表可以自定义吗？**  
A: 可以。修改`mysql_models.py`即可。

**Q: 如何处理失败的报告？**  
A: 查看`report_requests`表的`error_message`字段，根据错误信息处理。
